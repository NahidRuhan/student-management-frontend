# Student Management Frontend

## Project Overview
This is the frontend user interface for the Student Management Dashboard. It provides a sleek, modern, and responsive web application built with Next.js 16 (App Router), Tailwind CSS v4, and Redux Toolkit. It allows users to view a public list of students, and (if authenticated) add, edit, and delete student records.

## Requirements
To run this project, you will need:
- Node.js (v18 or higher)
- The Backend Service running concurrently (typically on port 4000) to serve API requests.

## Installation
First, install all necessary dependencies using npm:
```bash
npm install
```

## Environment Variables
Create a `.env.local` file in the root of the project directory. Next.js uses this to securely proxy requests to your backend server, avoiding CORS issues during development. **Do not commit real credentials or secrets to version control.**

```env
# The URL where your backend API is running
NEXT_PUBLIC_API_URL="http://localhost:4000/api/v1"
```

## Database Setup
The frontend does not require direct database setup. All database operations and schemas are handled and maintained by the NestJS backend service.

## Running the Application
To run the web application in development mode with hot-reloading:
```bash
npm run dev
```
Then, open your browser and navigate to `http://localhost:3000`.

## Available Scripts
Here is a list of important npm scripts provided in this project:
- `npm run dev`: Starts the Next.js development server on port 3000 with Fast Refresh enabled.
- `npm run build`: Creates an optimized production build of your application.
- `npm run start`: Starts a Next.js production server using the build generated by `npm run build`.
- `npm run lint`: Runs ESLint to statically analyze the code and catch errors.

## Additional Notes
- **API Proxying**: The Next.js configuration (`next.config.ts`) includes a rewrite rule that intercepts requests to `/api/v1/:path*` and forwards them to the backend server to avoid complex CORS configurations and ensure secure cookie forwarding.
- **State Management**: We use Redux Toolkit paired with RTK Query (`studentsApi` & `authApi`) to handle declarative data fetching, caching, and cache invalidation.
- **Authentication**: JWT Cookies are securely attached to every request via RTK Query's `credentials: 'include'` configuration. An `AuthWrapper` restores the user session seamlessly upon app initialization.
- **UI Architecture**: Primitive components are fully custom-built (using `clsx` and `tailwind-merge`) without relying on heavy external component libraries, allowing for maximum design flexibility.
